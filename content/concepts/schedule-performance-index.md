---
id: concept-schedule-performance-index
title: Schedule Performance Index (SPI)
tier: free
category: Project Process & Lifecycle
definition: >
  A ratio comparing the value of work actually completed to the value of work
  that was planned to be completed by this point, used to measure whether a
  project is running ahead of or behind its planned schedule, independent of
  whether it's also running over or under budget.
whyItMatters: >
  [[concept-cost-performance-index|CPI]] measures cost efficiency; SPI measures
  schedule efficiency, and a project can score well on one while scoring
  poorly on the other, so tracking SPI alongside CPI catches a schedule slip
  that a purely cost-focused report would miss entirely.
example: >
  A project has completed sixty percent of its planned work by a milestone date
  when the schedule called for seventy-five percent to be done by then. The
  resulting SPI below one flags a real schedule problem, even though the
  project's CPI that same month looks perfectly healthy, since the work that
  was completed happened to be done efficiently.
careerAngle: >
  The [[career-cost-engineer|Cost Engineer]] calculates SPI alongside CPI as
  part of routine project reporting, and the [[career-scheduler|Scheduler]]
  investigates the underlying schedule slippage an SPI below one is actually
  pointing to.
whatGoesWrong: >
  A project team tracks CPI closely but never calculates SPI, assuming a healthy
  cost position means the schedule must be fine too, and only discovers the
  project is genuinely behind once the finish date itself starts visibly
  slipping.
