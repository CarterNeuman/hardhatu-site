id: concept-cloud-document-control
title: Cloud-Based Document Control
tier: free
category: Technology, Data & Sustainability
definition: >
  Managing a project's drawings, specifications, and other controlled documents through
  a shared, version-tracked cloud system, so everyone on a project opens the same current
  set instead of whatever version happens to be in their own inbox or printed set.
whyItMatters: >
  Working from an outdated drawing is one of the most common, and most avoidable, sources
  of field rework. A superintendent building from last week's set after a revision went
  out is a paperwork failure, not a construction one. Cloud-based document control
  removes the ambiguity about which version is current by making there only be one.
example: >
  An architect issues a revised drawing set, and the cloud document system automatically
  marks the previous set superseded across every device on the project. A field tablet
  that opens the drawings the next morning shows the current revision without anyone
  having to manually distribute it.
careerAngle: >
  A [[career-project-engineer|Project Engineer]] maintains the current drawing set and
  distributes revisions through the system as part of routine documentation work. A
  [[career-project-manager|Project Manager]] depends on the same version control to keep
  [[concept-as-built-drawings|as-built documentation]] accurate throughout the project,
  not just reconstructed at closeout.
whatGoesWrong: >
  A field crew keeps working from a printed drawing set instead of checking the cloud
  system for the latest revision, assuming their set is still current. A dimension change
  issued days earlier never reaches them, and they build to the outdated dimension before
  anyone notices the printed set was already superseded.
